Independent source review: predicate ranges with saved disk configuration
Source reference: 7b2c37da; runtime/test/build/CI paths match 36183807.

No correctness blocker found in the combined implementation.

API and pruning
- The two with_filter initializers take separate predicate, borrowed context,
  and optional routing-key arguments. No data_config predicate callback is added.
- A routing key without a predicate returns EINVAL. Predicate-only scans retain
  all branches. Pruning requires every accepted stored key to hash like the
  representative query key for every possible seed, as documented publicly.
- routing_filter.c:1558-1626 validates the saved descriptor before calling the
  hash function and selects that descriptor's seed. The four-entry seed/hash
  cache only affects recomputation; eviction cannot remove candidate branches.
- merge.c:437-445 rejects keys before message merging/finalization. This avoids
  invoking merge callbacks on unrelated collision keys with incomplete histories.
  Direction changes restore the filtered operations. All memtables participate.

Ownership and error cleanup
- core.c:2148-2172 copies the representative key while borrowing predicate
  context. Span teardown retains filter state; iterator teardown releases it.
- trunk.c:7657-7678 validates selected branch roots through the B-tree module
  before acquiring references. Failed partial collection resets the count;
  outer cleanup releases references acquired for earlier complete bundles.
- Existing regressions cover persisted seeds 11/22 with construction default99,
  six-seed cache eviction, seed-dependent collisions, noncommutative updates,
  deletions, bounds, reverse movement, key-buffer reuse, thread handoff, and
  errors both while skipping rejected keys and merging accepted keys.

Shared AIO behavior examined after the disk short-range outlier
- core.c:1988-2010 resumes ready branch initializers and calls cache_cleanup
  when none advances. clockcache.c:48-49 and :522-524 pass a quota of one event
  to io_cleanup.
- platform_linux/laio.c:778-791 counts completed events, not polling attempts.
  laio_cleanup_one at :146 polls io_getevents with mincnt0; :159-160 returns0
  when no completion is available, leaving the caller in its polling loop.
- The cleaner at :184-189 shares the process AIO context. io_count remains
  positive through callback and submission-waiter processing (:173-178).
  Another thread can consume the caller's completion and mark its initializer
  ready, yet the caller continues polling until it wins another completion or
  the process-wide outstanding count reaches zero.
- This is an existing unbounded-work/fairness weakness and a plausible latency
  amplifier under I/O contention. Source review establishes no circular wait
  or candidate-specific progress bug. The cache and AIO source files match main.
  No shared-path change is included in this PR.
- The original outlier was not sampled, so normal-run profiles cannot establish
  its cause. User-only hardware counters exclude kernel execution; dividing
  cycles:u by total task-clock does not estimate CPU frequency for these
  kernel-heavy disk workloads. Subsequent kernel-inclusive measurements and
  sampled runs must be interpreted within their recorded scope.

Audit scope
review-readiness.py verifies source/ancestry, raw benchmark results and their
provenance, artifact hashes, phase gating, worker placement, disk storage,
serialization, and applicability of existing validation. It does not establish
statistical performance neutrality or replace the full compiler/sanitizer CI
matrix. Historical standalone measurements remain historical.

Ordinary range path compared with disk-format
- With no predicate, filter_query is NULL, every branch is selected, and the
  original merge allocation and operations are used. No predicate or routing
  hash callback runs. Prefetch budget and branch counts, branch iterator order,
  async initialization/draining, and page-reference release timing are retained.
- B-tree iteration/prefetch, cache, mini-allocator, and AIO source are unchanged.
  Added ordinary-path work consists of null checks, initializer helper/layout
  changes, and iterative empty-span restart instead of recursion. The appended
  filter pointer adds eight bytes to core_range_iterator without moving its
  existing fields, though it shifts fields in the enclosing public iterator.
  A bundle's references are now incremented in collected reverse order instead
  of descriptor forward order; initialization still uses the same branch order.
- No deterministic prefetch/concurrency mechanism for the observed long-range
  tail differences was established from these changes. The measurements need
  their own repeatability assessment; source similarity alone does not dismiss
  a performance signal.
