# Filter predicate and disk-format integration proof

This archive belongs to `robj/filtered-ranges-disk-format`, which merges
`cf7dc4f7` (filtered predicates on current main) and `3e302c04` (disk-format on
current main). The companion combines two independent feature branches solely
to validate their interaction. No combined-branch performance claim is made.

Routing lookup validates descriptors before invoking the hash callback and uses
the saved seed. Selected B-tree roots are validated in the B-tree module before
the trunk acquires their references. The iterator retains its copied routing key
across spans and hashes it separately for each encountered saved seed.

Debug and release each passed 125 unit cases: 56 quick API cases, 41 internal
core/recovery cases, 16 superblock cases, 10 merge cases, and 2 trunk async cases.
Both modes also passed the full routing-filter functional suite (four basic
cases plus structural regressions), including the new six-seed cache-eviction
and descriptor-validation checks. Focused mixed-seed database reruns passed in
both modes. All fixture databases were in private directories on real ext4
storage; no database files, executables, or core dumps are included here.

The six-seed test records the exact seven hash callback seeds generated by a
four-entry cache and verifies that empty, NULL, and invalid descriptors are not
hashed. The reopened database test exercises actual persisted seeds 11 and 22
while the construction default is 99. Tenants collide in the full 32-bit hash
only at seed 11. Eight scan variants verify complete noncommutative update
values, deleted keys, live memtable data, bounds, and both directions across
trunk leaves. Initial versus final seed masks prove another seed is first hashed
after the caller's template buffer is overwritten; the callback verifies the
iterator retained the original bytes.

`validate.py` records exact commands, working directories, statuses, and log
hashes. The active worktree used `BUILD_ROOT=build-filter-disk-integration`.
Representative invocations, from the campaign workspace, were:

```
python3 coordination/run_job.py --name filter-disk-debug-units build -- python3 coordination/filter-predicate-20261013/integration/validate.py build debug
python3 coordination/run_job.py --name filter-disk-debug-core test -- python3 coordination/filter-predicate-20261013/integration/validate.py test debug merge splinter superblock trunk-async
python3 coordination/run_job.py --name filter-disk-debug-quick-final test -- python3 coordination/filter-predicate-20261013/integration/validate.py test debug quick
```

The corresponding release commands and all focused builds/runs are retained in
`jobs.json` and the result JSON files. Scripts retain the original absolute
worktree paths; update those paths when reproducing in another checkout.
`source-sha256.json` and `binary-sha256.json` identify the validated artifacts.
The final formatter check and `git diff --check` passed.

Two initial mixed-seed fixture failures are preserved. The test compared slice
pointer identity (`slice_equals`) instead of key contents; diagnostic output
showed matching key bytes, and changing the assertion to `slice_lex_cmp` fixed
the fixture without a runtime change. Its first short probe accidentally omitted
the outer job wrapper, but another correctness suite held the shared machine
lock throughout it, excluding timed benchmarks. Later runs used the wrapper
explicitly. Fault-injection cases in the passing core suites intentionally emit
I/O error and reclamation warning messages.

`archive-manifest.json` covers every archived file except itself. The merge
commit containing this archive is the tested source snapshot; the manifest
records content hashes rather than a self-referential commit ID.
