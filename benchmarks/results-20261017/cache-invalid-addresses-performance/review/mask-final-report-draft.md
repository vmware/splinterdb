Async-mask final report outline — pending final performance measurements

The selected patch preserves invalid-address rejection while reducing cache lookup work in three places: it keeps diagnostic formatting in a cold helper, moves async miss allocation validation into the existing disk-load coroutine, and replaces the hot page-alignment remainder with a mask. A release-active assertion establishes the already required power-of-two page size before configuration computes its shift or division. Synchronous allocation validation stays inline. Invalid misses still fail before reserving a cache entry or submitting I/O; coroutine retry/resume and callback ownership are unchanged. The modulo operation also exists in main, so its replacement is a general improvement, not the removal of an operation newly introduced by invalid-address handling. An allocated nonblocking miss has an irreducible semantic difference: main may return BUSY immediately after the directory miss; this branch must first distinguish allocated from invalid/unallocated addresses. The mask does not remove that allocator membership check. Three direct production nonblocking-get sites are metadata-cursor operations in `mini_allocator.c`; ordinary scans do not issue one such miss per tuple. Their actual dynamic frequency has not been counted, so a microbenchmark percentage is not a measured database regression or a numerical bound on one. [Call-path review](long-scan-path-review.json)
